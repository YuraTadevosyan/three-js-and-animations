# evolution-of-ui

**The Evolution of UI:** sixty years of interfaces on one scroll.

The same little computer (a note, a photo of a lake, and three messages from
people who worry about you) is redrawn by every decade it lives through. Each
era is usable, not a screenshot. Type into the DOS prompt, drag Windows 95
windows, rate the photo on a Web 2.0 site, archive a message in Material and
undo it, tilt the glass, talk to the 2040 hologram. Whatever you change travels
with you: a line added with `ECHO … >> NOTES.TXT` in 1980 is on the glass widget
in 2025 and in the hologram's memory panel in 2040.

**Live:** <https://yuratadevosyan.github.io/three-js-and-animations/evolution-of-ui/>

| t | Year | Era | What's real |
| --- | --- | --- | --- |
| 0.6 – 1.4 | 1980 | DOS | An 80×25 text-mode machine with `DIR`, `TYPE`, `ECHO >`/`>>`, `MAIL`, `VIEW LAKE.PCX` (ANSI half-block art, dithered to CGA), history, PC-speaker beep, all drawn through a WebGPU CRT shader. |
| 2.0 – 2.6 | 1995 | Windows 95 | A window manager (drag, focus, minimise, maximise, taskbar), Start menu, Notepad, Paint with working tools on a 16-colour Bayer-dithered photo, an Exchange inbox, a real Minesweeper, message boxes and "It's now safe to turn off your computer." |
| 3.0 – 3.6 | 2005 | Web 2.0 | A glossy social site named *notr*, with a beta badge, reflected logo, NEW! starburst, polaroid, tag cloud, star rating, digg counter, an AJAX spinner and the Yellow Fade Technique. |
| 4.0 – 4.6 | 2015 | Material Design | App bar with tabs and an ink bar, cards on real elevation, a floating-label text field, switches, ink ripples, a FAB, a snackbar with UNDO, and a navigation drawer. |
| 5.0 – 5.6 | 2025 | Glassmorphism | Frosted panels over drifting colour with a pointer-tracked specular highlight and tilt, a notification stack that fans out, now-playing, and a control centre. |
| 6.05 – 6.6 | 2040 | Sci-fi UI | The lake photo rebuilt as a ~49 000-point WebGPU hologram with compute-shader physics, a HUD, a voice call from Mom you can finally answer, and NEXUS, an assistant you can type or talk to. |

## Stack

| | |
| --- | --- |
| Framework | [Qwik](https://qwik.dev/) 1.20 + Qwik City, **static** (SSG) output |
| Scroll | Native **CSS scroll-driven animations** (a view timeline drives one registered `@property`) |
| 3D / effects | **WebGPU** + hand-written **WGSL**: a render pipeline for the CRT, a compute pipeline and an instanced render pipeline for the hologram |
| Fallbacks | DOM text mode, Canvas 2D hologram, JS scroll mirror |
| Speech | Web Speech API (recognition and synthesis), optional |
| Styling | Tailwind v3 for the chrome; each era's own stylesheet via `useStyles$` |
| Build | Vite 7, TypeScript 5.8, eslint-plugin-qwik |

Qwik, WebGPU, WGSL, compute shaders and CSS scroll timelines are all new to
this repo. The app ships **no binary assets**: the "photo" is a seeded function
(`src/lib/landscape.ts`), the icons are inline SVG, and the only file emitted
beside the code is `lake.svg`, generated from that same function at build time.

> **Vite is pinned to 7.x.** Qwik 1.x declares `vite >=5 <8`. Vite 7 needs
> Node ≥ 20.19, which is what the rest of the repo builds on.

## One number

The page is a single tall track and a sticky stage. Scrolling the track moves
**`t` from 0 to 7**: whole numbers are eras, fractions are the transitions
between them (`src/timeline/eras.ts` has the table).

```css
@property --t { syntax: '<number>'; inherits: true; initial-value: 0; }
.track { view-timeline: --track block; }
.stage { animation: eou-t linear both; animation-timeline: --track; animation-range: contain; }
```

Every transition on the page is a pure CSS function of `var(--t)`:
`clamp()`, `calc()`, `color-mix()`, `sin()`. That includes the CRT warming up,
Internet Explorer growing out of its desktop icon, the Web 2.0 gloss draining
toward Material indigo, Material's ink flood, the glass panels rising, and the
HUD scanning in. So scrubbing backwards is exact, and the choreography needs no
animation library at all.

Two tricks worth knowing:

- **The year counter is pure CSS.** `--year` is a registered `<integer>`, set
  to a piecewise `calc()` of `--t` (generated by `yearCalc()`), and fed into
  `counter-reset`. The `<integer>` syntax does the rounding.
- **Visibility can't be computed**, and parked eras must not be painted or
  clicked. So one inline boot script (`src/timeline/boot.ts`, ~40 lines, runs
  before first paint) sets `data-live` on the stage to the list of layers whose
  window contains `t`. It also mirrors `t` into `window.__eou` for the WebGPU
  renderers. Where scroll timelines are missing it writes `--t` itself, so every
  browser runs the same CSS.

### Transitions that use the real thing

- **DOS → Windows.** Scrolling types `W`, `I`, `N`, Enter at the prompt, and the
  screen goes blank. The CRT tears through a video-mode switch, and the
  Windows 95 boot splash fades in over it.
- **Windows → Web 2.0.** An Internet Explorer window zooms out of its desktop
  icon and maximises. The 2005 layer is `clip-path`ped to the browser's
  viewport and translated to its top-left, so for a moment you're looking at the
  web through IE. Then the chrome melts away.
- **Web 2.0 → Material.** Every gradient on the page is a `color-mix()` toward
  indigo or paper white, every radius and shadow scales, all driven by one
  variable (`--gloss`). The skeuomorphism visibly drains out, then the Material
  FAB pops in and its ink floods the screen (a growing `circle()` clip).
- **Material → Glass.** The glass layer deliberately has no `opacity` or
  `filter` on any ancestor of its panels. Either would make that ancestor a
  *backdrop root* and cut the panels off from the page behind. So while they
  rise, their `backdrop-filter` is frosting the actual Material UI underneath.
- **Glass → 2040.** The panels let go and ~49 000 points are born inside them
  (their rects are sampled while 2025 is still whole). The points fly into a 3D
  reconstruction of the photo.

## The same little computer

`src/state/world.ts` is one Qwik store: the note, three messages (read and
archived flags), Wi-Fi, Bluetooth, Focus, and Mom's call. Every era renders it
in its own idiom, and it persists in `localStorage`.

| Thing | 1980 | 1995 | 2005 | 2015 | 2025 | 2040 |
| --- | --- | --- | --- | --- | --- | --- |
| The note | `TYPE NOTES.TXT`, `ECHO … >>` | Notepad | "What are you doing right now?" | Text field card | Glass widget | Memory panel, "remember …" |
| Messages | `MAIL`, `MAIL 1` | Exchange inbox | Your wall | Two-line list, archive + UNDO | Notification stack | Comms, and a call from Mom |
| Wi-Fi | `MAIL` says `NO CARRIER` | Tray icon | IE-style offline bar | Switch | Control centre | `LINK OFFLINE` |
| The photo | `VIEW LAKE.PCX` (CGA, half-blocks) | Paint (16 colours, Bayer) | Polaroid | Card media | Ambient glow | Point cloud |

Clocks everywhere show the real time of day, but in the era's year, with the
weekday that date actually had then. 27 September was a Saturday in 1980 and
a Wednesday in 1995. One imperative interval updates every `[data-clock]`,
so ticking time never wakes a Qwik component.

## WebGPU

One `GPUDevice` (`src/gpu/device.ts`) configures two canvases.

**The CRT** (`src/gpu/crt.wgsl`) samples a 1280×800 text-mode canvas at 4:3.
It adds barrel distortion, convergence error, a two-ring phosphor bloom,
scanlines that thin out on bright text, an aperture grille, vignette, flicker
and grain, plus the warm-up (a dot, a line, a picture) and the video-mode tear.

**The hologram** (`src/eras/scifi/scene.ts`) is not a picture of the photo. It
re-derives the scene from the same seeded ridge functions that drew it. The
mountains keep their silhouettes, the sun sets into the same valley, and the
pines stand on the same shore. Now there is depth, a reflection in the water,
stars and two instrument rings.

- `holo-sim.wgsl` (**compute**, 64 per workgroup) hangs every point on a damped
  spring from its home and pushes it away from the pointer in screen space.
  Click to kick harder.
- `holo.wgsl` draws one instanced, additively blended quad per point. It handles
  birth in a glass panel, the swirl in flight, ring orbits, twinkle, water
  shimmer, cyan tint, moving scanlines, a sweeping scan plane, the "show me the
  lake" pulse, and the final collapse into one point of light.

Per-point data travels as instanced vertex buffers rather than vertex-stage
storage buffers, which some WebGPU implementations limit. The compute pass
writes the offset buffer the vertex stage reads.

## Resumability

The whole page, all six eras included, is pre-rendered HTML. Qwik loads nothing
until something needs it:

- scrolling through every transition runs **no framework code**;
- the two heavy runtimes, the DOS terminal + CRT (`dos/mount.ts`) and the
  hologram (`scifi/mount.ts`), are dynamic imports fetched only when `t` comes
  near their era (`whenNear()` in `src/timeline/progress.ts`). The smaller
  setups (Paint's canvas, Material's ripples, the glass lighting) ship with
  their component's task but also wait for `whenNear()` before doing any work;
- a click handler's code downloads on its first click.

## Degradation

| If | Then |
| --- | --- |
| No WebGPU (or `?gpu=off`) | DOS draws into the `<pre>` with CSS scanlines and a CSS warm-up; the hologram renders ~10 000 points on a 2D canvas with the same camera and choreography, without physics. |
| No CSS scroll-driven animations | The boot script writes `--t` from a rAF-throttled scroll listener; all the same CSS runs. |
| No JavaScript | Every era is in the HTML; a `<noscript>` rule un-hides the layers and (in browsers with scroll timelines) the transitions still play. |
| `prefers-reduced-motion` | No CRT flicker, no auto-orbit or physics, no drifting blobs or tilt, no ripples; scroll-scrubbed transitions remain, since the visitor drives them. |
| `localStorage` blocked | The world lives for the visit. |
| No Web Speech | The mic button doesn't render; typing still works. |

## Verifying without a browser

```bash
npm test             # logic tests (scripts/tests.ts, bundled by esbuild)
npm run check:wgsl   # compile + run the shaders in Dawn (see below)
```

`npm test` covers:

- every DOS command, including that `ECHO` redirects, `CLS` and a bare Enter
  put the prompt exactly where DOS did;
- Minesweeper over 2000 seeded games;
- the year curve and live/dwell windows;
- era weekdays;
- NEXUS intents;
- the lake's geometry;
- the inline boot script, run against a fake DOM with and without native
  timelines;
- **the hologram's framing**: it projects every point through the real camera
  and asserts the reconstruction fits on screen at 16:9 and 9:16. That test is
  what caught the first version being a thin strip across the middle.

`check:wgsl` compiles all three shaders with Dawn (Chrome's WebGPU, via the
`webgpu` package for Node). It builds the exact pipelines the app builds, draws
the CRT once, runs thirty hologram simulation steps, and checks the physics
produced no NaNs and actually moved points near the pointer. The package is
~90 MB of native binaries, so it is not a dependency:

```bash
npm i --no-save webgpu@0.6.1 && npm run check:wgsl
```

## Notes for anyone editing this

- **Internet Explorer must stay the fourth desktop icon.** The 2005 transition
  grows its window from that slot: `--ie-t` in `win95.css` is `8px + 3 × 76px`.
- **Nothing inside a layer may set `visibility: visible`**, or it leaks through
  while the layer is parked.
- **Don't put `opacity` or `filter` on `.layer-glass`** or `.gl-grid`. See
  *backdrop root* above.
- **Don't transition anything whose value depends on `--t`.** A CSS transition
  trails behind the scrollbar and restarts every frame. (Material's cards had
  one; it's gone.)
- **Case-insensitive filesystems:** `Minesweeper.tsx` and a `minesweeper.ts` in
  the same folder resolve to the same module on macOS. The logic lives in
  `mines.ts`.
- **Links in the eras must never be `href="#"`.** A hash jump scrolls the page,
  which here means time-travelling to 1980. Decorative links are spans.
- `LIVE` windows in `eras.ts` must enclose each era's dwell *and* its
  transitions. `npm test` checks the dwell part.

## Local development

```bash
npm install
npm run dev        # http://localhost:5187/three-js-and-animations/evolution-of-ui/
npm run build      # client + static generation + tsc + eslint
npm test
```

Add `?gpu=off` to the URL to see the fallback path.

## Deploying

```bash
npm run deploy     # gh-pages -d dist/three-js-and-animations/evolution-of-ui -e evolution-of-ui
```

Qwik mirrors the Vite `base` into the output tree, which is why the deploy
directory is nested.
